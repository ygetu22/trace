# Trace hosting design and setup

**Not deployed yet.** This is the planned setup for running checks on a separate Linux worker. The gateway here still runs the older investigation flow and doesn't have the per-visitor quota from the local server yet, so the two need to line up before this goes live.

Until this setup has been tested on the real worker host and the checks below pass, the portfolio only shows a sample report and live checks stay off.

## Separation

`yakobgetu.com/projects/trace` belongs to the existing Next.js portfolio. Its server validates inputs, verifies Cloudflare Turnstile, and contacts an authenticated gateway over HTTPS. Browsers never receive the gateway service key or Turnstile secret. The gateway belongs on a dedicated Linux VM, separate from the portfolio, personal data, deployment credentials, and other applications.

The gateway creates one temporary Docker container per investigation. That container has no secrets, host mounts, Docker socket, cloud identity, or public inbound port. It runs as `pwuser`, with Chromium's sandbox enabled, a read-only image, all capabilities dropped, no new privileges, a version-matched seccomp profile, a 1 GB RAM limit without swap, one CPU, 256 processes, 256 MB private shared memory, and a 128 MB temporary filesystem. The gateway gives it a JSON request over stdin and receives bounded JSON/evidence over stdout. It does not run shell commands derived from URLs.

The browser container joins only `trace-isolated`, an internal Docker network. The only peer is `trace-egress`. That proxy listens only on its isolated-network address; it alone has an internet-facing network. It validates every HTTP request and HTTPS tunnel destination, rejects private/reserved/metadata addresses and nonstandard ports, and pins vetted IPs to prevent a second DNS lookup from changing the connection. DNS failures deny access. Browser redirects and resources use that same boundary. The proxy's outer interface has no listener and no published port. Neither container receives gateway keys. The Docker CLI launched by the gateway also receives only `PATH`, rather than inheriting gateway secrets.

Containers share the host kernel. A container is not a guarantee against browser or kernel exploits. Use a dedicated, patched VM without unrelated services or credentials. The gateway's Docker permission is effectively host administrative authority; it is trusted control code and must never serve arbitrary commands or paths. Do not put this permission on the portfolio host. Disable cloud instance metadata/instance identity for the worker VM where the provider permits it.

## Admission and evidence

One gateway process handles at most one investigation, with a 15-second start cooldown and 12 attempts per rolling hour. Failed admitted requests also count. There is no queue or automatic retry. A 100-second gateway deadline cancels the job; the browser has its existing 90-second investigation deadline. Docker containers are explicitly removed and absence is verified. An uncertain container creation or cleanup disables further jobs until an operator investigates and restarts the gateway. Automatic service restart is disabled so a crash cannot repeatedly reset admission limits or ignore orphan containers.

Evidence is capped at 24 MB per run, reports at 512 KB, and gateway stdout at 34 MB including base64. Four runs can be retained. Evidence stays in memory, expires after 15 minutes, and is removed by a periodic sweep; restarting also removes it. Worker temporary files disappear with the container. Each run has a random 256-bit access token. Next keeps it in an HttpOnly, SameSite=Strict cookie scoped to that run, Secure in production. Artifact access needs both the server service key and the correct run token. Knowing a UUID is insufficient. Artifacts have strict filename allowlists and are never interpreted as HTML; JSON and traces are downloads. No directory listings or public run archive exists. Public example files are deliberately reviewed static assets, separate from private live evidence.

These limits apply to a single gateway. Do not run replicas without shared admission state. Restart resets the rolling quota. Before deployment, apply provider/edge request limits to `/api/trace/captures` (including failed verification) and the worker API, enforce body/time/connection limits, and set host/provider spending alerts. Turnstile is required in public mode, verified server-side, and checked for the exact portfolio hostname and `trace-investigation` action. It reduces automated abuse; it does not prevent every attack or replace edge limits. Do not trust arbitrary forwarded IP headers for quotas.

## Prepare a dedicated Linux host later

1. Choose a provider, region, patch/update policy, and a dedicated VM. Install supported Node 22+, Docker Engine/Compose, and Caddy from their official sources. Do not mount personal folders or share this machine with the portfolio. Firewall inbound access to HTTPS and restricted operator SSH; no public 3120/3121/8080 or Docker daemon ports. Set outbound firewall policy and disable unnecessary cloud identity/metadata. Check that `172.30.0.0/24` does not conflict with the host network.
2. Copy only Trace source, lockfile, and deployment files to `/opt/trace`; use `.dockerignore` for image builds. Never copy `.env`, local reports, personal data, or keys into the image. Run `npm ci`, `npm run check`, and `npm run build` from that directory.
3. Build and start the proxy: `docker compose -f deployment/compose.yaml up --build -d`. No ports are published. This also builds `trace-worker:local`. Before release, record the verified image digest and pin the base image to it; update the image, Playwright package, and seccomp profile together. The included profile comes from Microsoft's Playwright v1.63.0 source.
4. Run `npm run check:isolation`. It must prove direct public egress is blocked, host gateway access is refused, metadata/loopback targets are rejected by the proxy, and a sandboxed browser can load public HTTPS. Test additional host/private networks and IPv6 for the selected provider. The gateway repeats this real check before listening and refuses unsafe network/proxy configuration. Remove any orphan `trace-job-*` containers after inspection before restarting.
5. Create a unique random gateway service key using a secure secret manager (at least 32 random bytes). Put it only in the portfolio's server secret store and a root-owned `/etc/trace/gateway.env` with mode `0600`, containing `TRACE_SERVICE_KEY=...`. Do not print it, place it in shell arguments, or commit it. The systemd template expects an operator-created `trace` user with Docker permissions and Node at `/usr/bin/node`; adjust the verified Node path for the host. Install the service file only after the isolation test passes. Inspect logs without recording request headers, tokens, or report contents.
6. Configure `deployment/Caddyfile` with a worker hostname such as `trace-worker.yakobgetu.com`, then validate the config with Caddy before installing it. Set up DNS/TLS at deploy time. The gateway remains bound to loopback; Caddy forwards the API paths. Prefer firewall/private connectivity restricting the worker API to the portfolio host when the hosting provider supports it. TLS verification stays enabled and redirects are refused by the portfolio client. Configure Caddy/provider header/body read deadlines appropriate to 8 KB API requests and the 110-second investigation request. Test auth rejection through the real TLS endpoint.
7. Create a Cloudflare Turnstile widget restricted to the chosen portfolio hostname. Set the portfolio server variables documented in the portfolio repo's `docs/TRACE_SETUP.md`. Never use `NEXT_PUBLIC_` or Next's `env` config for secrets. Public mode requires HTTPS on both origins and the explicit `yakobgetu.com` or `www.yakobgetu.com` portfolio origin. Choose one canonical hostname and redirect the other at the edge.
8. Run the end-to-end acceptance checks below, then explicitly enable public mode. Keep the kill switch (`TRACE_DEMO_MODE=off`) available without changing source.

## Release acceptance checks

- Rerun current dependency audits, type/lint/build checks, browser regressions, and live captures. Audit the container image and Linux/browser patch levels; npm audit alone does not cover those layers.
- Verify missing/wrong service keys are rejected, client bundles have no secret values, gateway redirects never forward credentials, missing/invalid/replayed Turnstile tokens fail, hostname/action mismatches fail, and cross-origin submissions fail.
- Verify private, loopback, IPv4-mapped, link-local, cloud metadata, IPv6, mixed public/private DNS, DNS rebinding, redirects, and subresources cannot reach a host-side test listener. Verify direct browser egress is blocked outside the proxy. Confirm the only worker peer is the proxy.
- Verify cancellation, deadline, oversized evidence, full retention, proxy failure, and Docker creation/start/removal failure leave no running job or expose other runs. Kill the gateway during a job and verify the next startup refuses any orphan before accepting traffic.
- Verify a second visitor cannot read the first visitor's screenshots/reports/traces, expiration works, and all artifact responses are uncached. Verify HTTPS/cookie settings on the final domain and no secrets/tokens/visited page content enter access logs.
- Exercise real concurrent requests and edge limits; verify cost ceilings, alerting, gateway kill switch, and a restore/update procedure. Check existing portfolio routes in both themes and on small screens.
